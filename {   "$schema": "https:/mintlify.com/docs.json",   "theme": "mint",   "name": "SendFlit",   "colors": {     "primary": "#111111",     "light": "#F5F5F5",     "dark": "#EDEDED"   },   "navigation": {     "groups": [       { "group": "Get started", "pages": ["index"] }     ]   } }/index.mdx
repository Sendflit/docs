title: "SDKs"
description: "Official SendFlit SDKs for sending transactional email from your application or AI agent."
---

Every SendFlit SDK wraps the same REST API (`https://api.sendflit.com/v1`) and behaves the same way:

- **Zero dependencies.** Each SDK uses only its language's standard library or runtime HTTP client.
- **Retries.** `429` and `5xx` responses are retried with backoff, and `Retry-After` is honored. See [Errors, retries and limits](/reference/errors).
- **Idempotency.** The Node.js and Python SDKs accept an idempotency key on send and batch calls, so a retry never sends a duplicate. The other SDKs don't expose it yet.
- **Webhook verification.** Each SDK checks the HMAC-SHA256 signature in the `X-Sendflit-Signature` header. See [Webhooks](/reference/webhooks).

New here? Start with the [Quickstart](/quickstart) to verify a domain and send your first email.

<Warning>
  Until a package is published, its install command fails with "not found". Use the status column to check. Each SDK's source lives in its own repo under the `Sendflit` GitHub organization.
</Warning>

## Authenticate

Create an API key in the dashboard and pass it to the SDK. Keys look like `re_...`. Each key has a scope: `full`, `sending`, or `read`. See the [Quickstart](/quickstart#2-create-an-api-key) for the table.

<Warning>
  Keep API keys on the server. Don't ship them in browser or mobile code.
</Warning>
