title: "SDKs"
description: "Official SendFlit SDKs for sending transactional email from your application or AI agent."
---

Every SendFlit SDK wraps the same REST API (`https://api.sendflit.com/v1`) and shares the same behavior:

- **Zero dependencies.** Each SDK uses only its language's standard library or runtime HTTP client.
- **Retries.** 429 and 5xx responses are retried with backoff, and `Retry-After` is honored.
- **Idempotency.** The Node.js and Python SDKs accept an idempotency key on send and batch calls, so a retry never sends a duplicate. The other SDKs don't expose this yet.
- **Webhook verification.** Each SDK checks the HMAC-SHA256 signature in the `X-Sendflit-Signature` header.

</Warning>

## Authenticate

Create an API key in the dashboard and pass it to the SDK. Keys look like `re_...`.

<Warning>
  Keep API keys on the server. Don't ship them in browser or mobile code.
</Warning>

Each key has a scope:

| Scope | Can do |
| --- | --- |
| `full` | Everything, including key and domain management. |
| `sending` | Send email and read its delivery status. |
| `read` | Read-only. Cannot send. |

## Verify webhook signatures

SendFlit signs each webhook request with HMAC-SHA256 and sends the signature in the `X-Sendflit-Signature` header. Verify it against the raw request body before you parse the event. Every SDK exposes a verification helper. The language pages show the exact name.
